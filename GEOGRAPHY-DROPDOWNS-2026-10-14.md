# Geography dropdowns — local implementation

- One byte-identical Nigerian state vocabulary is bundled in Operations, staging Client Portal, the actual Client Portal source, staging backend and actual backend source. It includes 36 states and Federal Capital Territory; case/whitespace and known FCT/Abuja aliases normalise to canonical names. Misspellings are rejected, not guessed.
- Command-centre State, City/locality and Estate controls are selects. `/meta/estate-options` is authenticated, internal-only and requires Situation, Forecast or Properties read permission. Public/client/provider accounts cannot enumerate other clients' estates. Estate options are bounded to 100, with state/locality narrowing and name search; changing the parent resets dependent selections. Response guards discard stale option loads.
- Client signup requires a canonical state and submits it separately from the estate name and street address. The backend saves it to `properties.state` in the existing atomic registration transaction. New estate names and street addresses necessarily remain user-entered; no public estate directory is exposed. A typed address is not a verified locality, LGA, boundary or coordinate, and is not silently converted into one.
- Provider signup selects one or more coverage states using labelled checkboxes inside a disclosure, not modifier-key multi-select. Backend validation derives `coverage_area` from the canonical state array and ignores conflicting free-text coverage in this versioned flow. Coverage does not assign a provider to estates.
- Both forms send `locationSchema: ng-states-v1`. Legacy forms without structured state fields remain compatible; invalid supplied states are rejected before account INSERT. Existing misspelled data is not bulk-rewritten. Deployment must put the updated backend in place before these forms, otherwise an older backend may ignore the new fields.
- No database migration is required for this batch. Nothing deployed. No real accounts, verification emails or operational notifications were created during testing.

Verification: registration state/coverage contract tests, canonical-copy parity, estate picker HTTP tests against disposable PGlite (including client/provider denial and FCT aliases), both signup-flow suites with mocked APIs, backend bootcheck and local-readiness runner. Browser verified dependent state/locality/estate choices, zero-estate state, applied estate URL, provider multi-state selection and phone widths. The client property step is behind real email verification; its complete flow was exercised with mocked APIs, not by sending a real registration.
